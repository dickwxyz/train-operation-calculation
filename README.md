# 铁路行车组织算例教学演示

铁路行车组织教学演示 Web 应用，顶部统一三个标签页：

- **调车作业计划（`/`）**：按《铁路行车组织（第2版）》第四章第五节**按站顺编组摘挂列车的「调车表法」**求解——输入待编车列与股道条件，自动完成 **下落 → 调整(邻组) → 暂合候选 + 不合并基准 → 股道分配 → 逐钩作业计划**，分阶段展示，并可用逐步股道图回放每一钩后各股道/牵出线的车辆状态。
- **列车编组计划（`/bianzu`）**：第十一章技术站单组列车编组计划——选题后按算例集步骤展示**绝对计算法 / 表格计算法**的完整计算表、列车到达站图、最优方案与目标函数值。
- **教材问答（`/qa`）**：章节级 BM25 + bge-m3 向量召回，再由 DeepSeek 严格依据教材片段组织答案，带 `[编号]` 出处。

前端为原生 JS 静态页，无构建、无模板目录；面向学校局域网内多名学生并发使用（求解为毫秒级，`threaded` 开发服务器即可）。

## 功能特性

- **调车表法求解**：解析待编序列 → 下落列（与教材表 4.5/4.9/4.16 一致）→ 邻组化调整（自动复现表 4.6/4.17）→ 按「对口理论」枚举暂合候选，并始终附带**不合并基准**（方案零）；例4.4/习题3 另含「二·四·五」三列暂合。按时间模型（挂车钩×4 + 溜放钩 + 转线钩）标注最优。
- **分步可视化**：候选方案 chip 切换；每方案有钩计划表、股道分配（表格，停留道标“坐底”）、编成车列；统计三行并附公式（调车程 = 挂×2 + 溜 + 转；总钩数 = 挂 + 溜）；**逐步股道图**基于每钩内嵌的 `state` 直接渲染——车组按整体图形（1 辆=竖长方形、2 辆=正方形…，4 圆角、不折行/不重叠，组内每辆一个去向号），可 ⏮到开始 / 上一步 / 下一步 / 跳轮 / 到结尾。
- **内置算例**：例题 4.3/4.4/4.6 与习题 2/3/7/8/9/12 均可一键填充、直接求解（当前 `MODE="full"`）。
- **教学版锁定（例题白名单，开发时定死）**：`scripts/mode.py` 顶部 `MODE = "locked"` 时，服务端**只放行 3 个例题**，其余输入（习题原题、各种变形、自编数据）一律 403，习题按钮置灰。**当前为 `"full"`（2026-09 作业一收齐后放开）**；改回 `"locked"` 重新打包即恢复锁定。切换需改代码重传，学生端解不开——详见「教学版锁定」。
- **教材问答（`/qa`）**：面向期末复习的 RAG——全书 md 按章/节/表格/例题/习题结构切块并聚合到章节；先由 LLM 把口语问题改写成 2–4 条教材式检索式，再用 **章节级 BM25（词/字）+ bge-m3 向量** 混合召回（RRF），最后让 DeepSeek **严格依据检索片段**组织答案并标注 `[编号]` 出处。片段不足时明确说明，不补外部知识。命令行：`venv/bin/python -m scripts.rag.build_index` 建索引、`venv/bin/python -m scripts.rag "问题"` 提问、`venv/bin/python -m scripts.rag.eval` 回归。
- **编组计划算例（`/bianzu`）**：第十一章「技术站列车编组计划」演示页——例 11.3/11.5/11.6 与习题 1/2/3。顶部为 index 式预设按钮（例题 / 习题分组），点击后显示可编辑的已知信息（T集、t节、非短途车流车数）与默认结果；修改后点「计算列车编组计划」由**页面内嵌的 JS 求解器**重算，页面不刷新、无需后端（file:// 直接打开也能用）。计算过程：绝对计算法（4 站题：10 个方案各一张完整表 + 到达站图）→ 表格计算法（第 1–4 步：N通·t节 表、绝对条件 → 必要条件① → 必要条件②、初始方案、逐次调整、第 4 步选最优）→ 结论与 F耗/F节。表格按算例集形式；默认页面由 `scripts/build_bianzu_page.py` 生成，脚本内含教材结果断言。
- **三页统一框架**：标题「铁路行车组织算例教学演示」+ 标签页「调车作业计划 / 列车编组计划 / 教材问答」，当前页高亮；公共样式集中在 `static/style.css`（`bianzu.html` 另有少量内联样式）。
- 纯 Python 算法核心零第三方依赖（Flask 服务仅依赖 `flask`/可选 `jieba`）。

## 使用说明

三页通过顶部标签页切换。以下第 1–3 条为**调车作业计划**页；**列车编组计划**页见下一小节。

1. 顶部按钮可一键载入例题/习题（选中后按钮蓝底高亮，手动改输入即取消）；也可手填：待编车列、停留股道、可用作业股道（或条数预算）、出发股道、（字母站名时）站序。
   - 待编写法示例：`4₂ 5₂ 6₁…`（下标=辆数）、`4_2`、纯数字串 `736…`（每字符 1 辆）、字母 + 站序（如 `b₂a₁…` + 站序 `fedcba`）。
   - **教学锁定版**（`MODE="locked"`）下服务端只放行 3 个例题：习题原题、各种变形写法（换站序 / 展开 / 字母）、乃至自编数据都会被拒绝（403）。当前 `MODE="full"`，不受限。
2. 结果分五块：算例概览 → **下落**原始调车表 → **调整**（哪些车组移列、成什么邻组、调整后表）→ 各**候选方案**（首项为**不合并基准**；例4.4/习题3 另有三列暂合；★为暂合方案中的最优）→ 选中的方案里：统计 / 股道分配 / 钩计划表 / 编成 / 逐步股道图。
3. 逐步股道图：`⏮ 到开始 / ◀ 上一步 / 下一步 ▶ / 跳到下一轮 ▶▶ / 到结尾 ⏭`；左=远端(内)、右=机车端（🚂）。同一车组画成一个图形：辆数即格数（1 辆=竖长方形、2 辆=正方形…，4 圆角、组内无间隙、不折行不重叠），组间留隙；“第 N 轮”=第 N 次股道牵出/转线，该轮溜放同轮。

### 列车编组计划页（`/bianzu`）

1. 顶部「选择算例」按 index 式预设按钮分组**例题**（例 11.3/11.5/11.6）与**习题**（习题 1/2/3）；点击后显示该题的可编辑已知信息（T集、t节、非短途车流车数）与默认计算结果。
2. 修改数值后点击表单下方的 **「计算列车编组计划」**：页面不刷新，由页面内嵌的 JS 求解器本地重算并替换该题 panel（不依赖 Flask，`file://` 直接打开也可用）；切换题目会恢复默认数据与教材定稿结果。输入框为文本框，可直接键入，无上下箭头。
3. 每个 panel 的顺序：**绝对计算法（仅 4 站题）→ 表格计算法 → 结论**。
   - 绝对计算法：第一步枚举、第二步逐方案给出算例集格式的完整计算表 + 到达站图（10 套），第三步选 F耗 最小者。
   - 表格计算法：第 1 步 N通·t节 表；第 2 步（1）绝对条件的判断 →（2）必要条件①的判断（式 11.13）→（3）必要条件②的判断——剩余车流的合并（式 11.14，只检查（1）（2）都不满足的车流；交集只有相邻两段者只能编入摘挂列车），随后是初始方案表/图、F节 与绝对计算法验证；第 3 步逐个调整方案（表 + 图 + F节 + 验证）；第 4 步选最优。方案描述与结论只写开行的非短途直达列流（发站编号−到站编号 ≥ 2）。
4. 表格形式与 `knowledge_base/技术站列车编组计划的编制/技术站列车编组计划的编制-算例集.md` 一致：标签 `colspan=2`、`T集` / `t节`、各车流。绝对计算法的表另含 `N改编`、`N改编·t节` 两行；表格计算法的表不含这两行，而是在同位置放一行 `ΣN通·t节`（各中间站一列给该站 ○/△ 记号之和，末列给总计，即 F节 的被减数），随后是 `K_i·T集^i` 与目标函数行。绝对条件按教材式 `N_ij·min{t_k} ≥ T集^i` 判断（○/△ 记号）。
5. 默认页面是**静态生成产物**，不要手改 `static/bianzu.html`；修改题目数据或版式后运行：
   ```bash
   venv/bin/python scripts/build_bianzu_page.py
   ```
   脚本会断言 4 站 10 方案全表、5 站 150 方案最优值、6 题各阶段 F节/F耗 与教材一致，并把到达站图写入 `static/svg/bianzu/`。页面上修改数据后的重算由页面内嵌 JS 完成（默认数据仍显示构建期定稿 panel）；后端另保留一个可选的 `POST /api/bianzu`。
6. 可直接用 hash 打开某题：`/bianzu#p-ex11.3`、`#p-ex11.6`、`#p-xt3` 等。

### 教学版锁定（例题白名单，开发时定死）

> **当前 `MODE = "full"`**：2026-09 作业一收齐后放开，习题按钮已在页面上可点、答案可算。闸门代码原样保留，改回 `"locked"` 重新打包即恢复课堂锁定。以下描述的是**锁定态**的行为。

课上先讲 3 个例题，6 个习题留给学生自己做，做完再看答案。锁定在**开发时**完成，学生端解不开：

- **开关**：`scripts/mode.py` 顶部 `MODE = "locked"` / `"full"`；改完重新打包上传。启动日志会打印当前状态。
- **白名单**：锁定版**只放行 3 个例题**，其余输入一律 **403**。判定用"规范形"（逐辆去向 → 首次出现次序），它对三种变形都不变，所以换着法子写也绕不开：
  - **换站序 / 重命名站号**（如把站序设成 `7654321`）；
  - **展开写法**（`1₃4₁…` 写成 `111 4 …`）；
  - **书写格式**（下标 / `4_2` / 空格 / 逗号）。
- **闸门在服务端**：`/api/solve` 解析后判白名单，拒绝时返回 403 + 提示语。改前端 JS 或直接调 API 一样被拦。
- **前端**：习题按钮在 HTML 里写死 `disabled`（接口不可达则保持置灰，fail-closed）；`/api/mode` 回报 `exercise_locked: false`（即 `MODE="full"`）时才解除置灰，锁定态下另在输入区显示"仅开放例题"提示。
- **代价**：锁定版下**任何非例题输入都会被拒**——学生无法用自编数据练习，课堂变式也做不了。若要放开，把 `MODE` 改成 `"full"` 重新打包。

## API

### `POST /api/solve` — 调车表法求解

```json
{
  "seq": "4₂5₂6₁3₁5₂1₃2₁4₃3₂6₁5₁3₂1₁4₂7₂",
  "station_order": null,
  "home_track": "7",
  "allowed_tracks": ["7", "8", "9", "10"],
  "depart_track": "DF3",
  "weights": {"pull": 4, "throw": 1, "transfer": 1},
  "deep_merge": false
}
```

- `allowed_tracks`（含停留道）与 `track_budget`（条数，含停留道）二选一；都不给则不限。
- `deep_merge: true` 时额外枚举「合并下落列二、四、五」三列暂合候选（例4.4 / 习题3 的教材做法）；
  缺省 false，其他题目不受影响。
- 返回 `{success, meta, stages{xialuo, tiaozheng, track_budget}, schemes[], best_scheme_id, note?}`；
  每个 `schemes[i]` 含 `id/label/supercols/track_alloc/stats/hooks/final_formation/best/baseline/extra_tracks/deep`，
  每条 `hooks[j]` 含 `code/kind/qty/cars/phase_round/note/state`，`state={tracks, lead}` 即该钩后全场（前端零再推导）。
- `schemes` 首项固定为 `baseline=true` 的**不合并基准方案（方案零）**：不受给定股道数限制，
  按股道充足假设生成（不够时按数字道号递增补线，`extra_tracks` 列出补出的道），只作比较基准、不参与 ★ 评选；
  只有基准、没有暂合可行方案时（如未启用 `deep_merge` 的习题3）`best_scheme_id=null` 并带 `note` 提示。
- `deep=true` 的方案含 ≥3 列的超列（当前即「二·四·五」三列暂合），只在请求 `deep_merge=true` 时生成。
- 前端校验与后端镜像（`static/index.html` 与 `app.py` 注释互指），改输入规则需两处同步。

### `POST /api/bianzu` — 编组算例重算（可选服务端入口）

> 页面本身已改为**纯前端 JS 计算**，不再调用此接口；保留它供其他客户端或服务端集成使用。

请求（只允许改数值；题目与车流名固定）：

```json
{
  "key": "ex11.5",
  "T": [500, 540, 0, 0],
  "t": {"1": 4, "2": 3},
  "N": {"31": 95, "30": 115, "20": 185}
}
```

- 返回 `{success: true, html: "<section …>"}`；参数错误返回 400（未知题目、T 长度不符、t/N 名称不符、负值等）。
- 数据与题目默认值一致时返回教材定稿 panel（步骤与图不变）；修改后的数据走通用求解器：
  按绝对/必要条件构造初始方案 → 全枚举找最优 → BFS 找 F节 严格增加的调整路径 → 动态生成到达站图（内联 SVG）。

### `POST /api/qa` — 教材问答

```json
{ "question": "什么是调车钩？" }
```

返回 `{success, answer, qtype, mode, no_llm, queries, sources[{n, source, section, printed_page, block_type, score, snippet}]}`。
链路：LLM 查询改写（口语 → 2–4 条教材式检索式）→ 章节级 BM25（词/字）+ bge-m3 向量（numpy 索引，RRF 融合）
→ DeepSeek 严格依据检索片段组织答案。`mode`：`llm` / `llm_error`（模型失败，仍返回 sources）/
`index_error`（缺 `rag_index/` 或 `bge-m3/`）/ `no_result`。空问题 / 超过 500 字返回 400。

## 算法流程（简）

1. **下落**：把反顺序车组落到若干"列"，每列去向非降（表 4.5/4.9/4.16）。
2. **调整**：把边界可调车组移入相邻列形成**邻组**（v 与 v+1 相邻、同线、溜放省钩），复现表 4.6/4.17。
3. **暂合与基准**：按对口理论（列一不并、相邻列一般不并）枚举可行列分组；股道不足时也允许更密合并。
   **不合并基准**（方案零）不受股道限制，始终按股道充足假设生成并排第一；`deep_merge` 请求另加「二·四·五」三列暂合。
4. **股道分配**：含首车组列的**超列**坐底于停留道；其余超列给 allowed 中的其他道。
5. **钩计划**：初牵留坐底 → 溜放（同线连续车段合一钩，保留机前集结）→ 拆分暂合列（三列暂合时先把远端最大去向段留底、分轮归块后再挂回）→ 按去向降序连挂 → 转线。
   **轮次**＝每次“股道牵出 / 转线”开一轮，该轮内的溜放（含拆分归块溜放）与牵出同号。

### 堆序约定（全项目唯一，务必遵守）

> **任意股道 / 牵出线状态列表一律「机车远端(内/左) → 机车端(右)」，机车端恒在右。**
> 待编车列书写序 = 该序（索引 0 = 最远/内）。最终编成 = 去向 1..n 顺序，n 贴机车端。

（注意这与早期"分组选编法"的旧约定相反。）

## 已知限制

- **闸门只挡 `/api/solve`**：`/api/qa`（RAG 修好后）目前不过闸；届时若语料含习题答案需一并接入。页面源码里只有 6 个习题的**原题**（教材题面，非答案）；锁定态下求解请求在 `jsonify(result)` 之前就被拒，答案不会被返回。
- **锁定态下仅例题可用**：见「教学版锁定」——这是刻意的取舍，不是缺陷。当前 `MODE="full"`，闸门未生效。
- **三列暂合有条件出现**：只有 `deep_merge=true`（例4.4/习题3 预设默认开启；页面手动输入不发送该标记，
  其他客户端可自行传参）且 K=5、可用股道 ≥3 时，才加入「二·四·五」三列暂合；其他题目与旧客户端不会看到该候选。
  例4.4 复现算例集方案一（5挂7溜，钩序一致）；习题3（3 线）生成 5挂7溜答案。
  其余三列组合尚未纳入枚举（见 Roadmap）。
- **自动调整仅覆盖单对边界邻组**：对非教材算例给出的是引擎实测钩数（可运行、终列正确），未必等于某人工最优解。
- **教材问答依赖本地模型与索引**：`bge-m3/`（约 2.2GB，gitignored）与 `rag_index/`（生成数据，保留在根目录）；换机器需重新复制模型并跑 `scripts.rag.build_index`。bge-m3 CPU 建索引约 10–30 分钟，运行内存约 2–3GB。
- **教材问答严格依据片段**：片段不足时模型会明确说“教材原文未直接给出”；选择题不保证给出 A/B/C/D；计算题给公式与例题步骤、不替学生代入数字。第四、十一章补自块只能给印刷页范围（036–057 / 150–169）。
- OCR 噪声：教材原文 md 含少量错字（如 `t节`），`knowledge_base` 提炼已按上下文统一。
- Flask `debug` 由环境变量 `FLASK_DEBUG` 控制（默认关闭，仅排障时开启）；局域网并发量级小，`threaded=True` 够用。生产请换 WSGI。
